# 해설 문구 검토표 — PDF 원문 ↔ 화면 문구 (기계적 결함 대시보드)

발표자 검토용. 화면 문구의 원본은 `모터결함_애니메이션/애니메이션_해설.pdf` 2장(= `motor_dt_viz/docs/animation_guide.md`)이고,
화면에 나가는 문구는 `dashboard/public/content/mechanical/narration.yaml` 이다. **뜻을 바꾼 곳은 없다.** 바꾼 것은 세 가지뿐이다.

1. PDF 의 "보이는 것" 한 문단을 화면에서는 **왜 그런가 → 무엇이 보이나 → 그래서** 세 줄로 나누어 시간차를 두고 공개한다.
2. PDF 에 박힌 숫자(장면 종료 값)는 화면에서 `{변수}` 로 바꿨다. 값은 export 가 로그에서 채운다.
   "지금 …" 처럼 현재 상태를 말하는 줄은 `_now`(재생 시각의 값), 결과·인과 카드는 `_end`(장면 종료 값)를 쓴다.
   장면이 끝나는 순간 `_now` 값은 PDF 숫자와 같아진다 (자동 테스트 `test_guide_pdf_numbers_match_log` 가 PDF 18개 숫자를 로그와 대조).
3. "그래서" 줄은 PDF 에 따로 없던 **결론 한 문장**이다. PDF 의 멘트·결함 지문에서 뜻을 가져왔고 새 주장은 넣지 않았다.

멘트(`presenter_line`)는 PDF 그대로이며 발표자 화면에만 나온다.

| 장면 | PDF 원문 (2장) | 화면 (narration.yaml) | 비고 |
|---|---|---|---|
| 1 정상 운전 | 보이는 것: 모든 부품이 원래 재질 색이다. 권선 63.6 °C, 베어링 41.2 °C, 진동 1.0 mm/s. / 왜: 정격 부하에서도 동손·철손·마찰열이 생기지만 냉각팬이 그만큼 내보내 온도가 일정하다. | 왜: (원문 그대로, "동손(전류 때문에 생기는 열)" 풀이 추가) / 보이나: 모든 부품이 원래 재질 색 그대로입니다. 권선 {winding_now} °C, 구동측 베어링 {bearing_de_now} °C — 각각 허용 상한(…) 아래입니다. / 그래서: 이 상태의 온도가 '기준선'입니다. VIGENT 는 이 기준선에서 벗어나는 순간을 잡아냅니다. | "그래서"는 멘트 "이 상태가 기준선이 된다"에서. 허용 상한 값은 config. |
| 2 DE 베어링 열화 | 보이는 것: 구동측 베어링만 주황→빨강 발광, 엔드실드 반투명. 베어링 135.7 °C(위험), 진동 4.8 mm/s(Act). 권선 85.0 °C 정상. / 왜: 윤활 부족·마모로 마찰 손실이 커진다(5배). 열이 그 자리에서 나므로 베어링만 붉어진다. | 왜: (원문, 5배 → {loss_multiplier}) / 보이나: 구동측(DE) 베어링만 주황에서 빨강으로 변합니다. 지금 {bearing_de_now} °C — {bearing_de_stage_now} 단계 (주의/경고/위험 경계). 진동 {vib_now} mm/s ({iso_now_ko}). 다른 부품은 아직 정상입니다. / 그래서: 베어링이 주의 단계에 든 순간 VIGENT 가 경보를 보냅니다. 위험까지의 여유는 화면 {lead_s}초 = 시뮬레이션 약 {lead_sim_min}분입니다. | 엔드실드 반투명은 이벤트 자막("엔드실드가 반투명해집니다")으로 그 순간에 나간다. "권선 85.0 °C 정상"은 "다른 부품은 아직 정상"으로 축약(수치는 온도 차트에 있음). 리드 타임 값은 export. |
| 3 축 정렬 불량 | 보이는 것: 베어링 열은 81.7 °C 로 식어 가고 축(78.0 °C)과 코어 쪽이 따뜻해진다. 진동 3.6 mm/s(Plan). / 왜: 커플링 정렬이 틀어지면 축이 돌 때마다 휘어 양쪽 베어링에 하중이 걸린다. 열이 한 점이 아니라 축을 따라 퍼진다. | 왜: (원문 + "이 시나리오는 베어링 손실 {loss_multiplier}배에 축 발열을 더했습니다") / 보이나: 베어링 열은 {bearing_de_now} °C 로 식어 가고, 대신 축(샤프트)이 {shaft_now} °C (허용 {shaft_normal} °C)로 따뜻해집니다. 진동 {vib_now} mm/s ({iso_now_ko}). / 그래서: 열이 한 점이 아니라 축을 따라 퍼지는 것이 이 결함의 지문입니다. 정렬 불량은 온도보다 진동에서 먼저 드러납니다. | "코어 쪽"은 뺐다(온도 차트에서 코어 선이 보인다). "그래서"는 원문 마지막 문장 + 멘트. |

## 이벤트 자막 (PDF 에 없던 문구)

자막은 로그에서 자동 추출한 사건(`events.json`)을 `event_templates.yaml` 로 문장화한 것이다. PDF 원문이 없으므로 아래 템플릿만 검토하면 된다.

| 사건 | 템플릿 |
|---|---|
| 등급 상승 | `{part_label} {threshold_C} °C 돌파 — {to_ko} 단계` |
| 등급 상승(주목 부품이 주의 진입 = 조기 경보) | `… 주의 단계 (VIGENT 조기 경보 시점)` |
| 위험 진입 | `{part_label} {threshold_C} °C 초과 — 위험 단계, 빨강 발광` |
| 등급 하강 / 정상 복귀 | `… 아래로 — {to_ko} 단계로 내려옴` / `{part_label} 정상 범위 복귀 ({threshold_C} °C 아래)` |
| 진동 등급 | `진동 {threshold_mms} mm/s 초과(아래로) — ISO 20816-3 {to_ko} 등급` |
| 투시 | `엔드실드가 반투명해집니다 — 안쪽 베어링이 보입니다` / `… 다시 불투명해집니다` |
| 장면 전환 | `장면 {label} — 화면 1초 = 시뮬레이션 {time_scale}초` |

## 인과 카드 (PDF 4장 요약)

원인 → 메커니즘 → 결과 → 조치 네 칸은 PDF 4장(결함별 설명)과 2장의 "왜"를 한 줄씩으로 줄인 것이다. 조치 문구("재윤활 또는 베어링 교체",
"레이저 정렬로 커플링 재정렬", "팬·커버 청소 또는 교체", "에어갭 조정, 라이닝·스프링 점검", "부하를 정격 이하로 제한")는 일반적인 정비
조치이며 시뮬레이션 결과가 아니다. 발표에서 근거를 물으면 "일반 정비 지침"이라고 답한다.

## 고치는 법

`narration.yaml` / `event_templates.yaml` / `qa.yaml` 을 고치고 브라우저 새로고침만 하면 된다(빌드 불필요, 런타임에 읽는다).
숫자는 절대 직접 쓰지 말고 파일 머리에 적힌 변수를 쓴다. 변수 오타는 `pytest tests` 가 잡는다.
