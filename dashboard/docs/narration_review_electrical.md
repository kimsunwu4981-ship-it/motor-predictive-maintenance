# 해설 문구 검토표 — PDF 원문 ↔ 화면 문구 (전기적 결함 대시보드)

화면 문구의 원본은 `모터결함_애니메이션/애니메이션_해설.pdf` 3장(= `motor_dt_viz/docs/animation_guide.md`)이고,
화면에 나가는 문구는 `dashboard/public/content/electrical/narration.yaml` 이다. **뜻을 바꾼 곳은 없다.** 바꾼 것은 다음뿐이다.

1. PDF 의 "보이는 것 / 왜" 를 화면에서는 **왜 그런가 → 무엇이 보이나 → 그래서** 세 줄로 나누어 시간차를 두고 공개한다.
2. 숫자는 `{변수}` 로 — "지금 …" 줄은 `_now`(재생 시각 값), 결과·인과 카드는 `_end`(장면 종료 값). 장면 끝에서 `_now` = PDF 숫자
   (자동 테스트 `test_guide_pdf_electrical_numbers_match_log` 가 PDF 3장의 8줄·1장의 임계 암페어 5개를 로그·config 와 대조).
3. 상 이름은 `{ph_a}/{ph_b}/{ph_c}` 변수 → config `phase_labels` 의 **R·S·T** (2026-09-22 결정, 내부 키는 A/B/C). PDF 도 R·S·T 로 고쳤다.
4. "그래서" 줄은 PDF 멘트의 결론을 한 문장으로 옮긴 것이며 새 주장은 없다.
5. `data_source_note`(규칙 5): 장면마다 "해석식 3상 모델 / 등가 표현 / 단락 루프는 시각적 표시 / 전압은 모델 입력 아님" 을 짧게 표기.

## 이벤트 자막 템플릿 (PDF 에 없던 문구)

| 사건 | 템플릿 (`event_templates.yaml`) |
|---|---|
| 상 상태 변화 | `{phase_label} {rms_A} A — 정격의 {pct} %, 위험 과전류 ({threshold_A} A 초과)` 등 상태별 5종, 정상 복귀 |
| 세 상 동시 | `세 상 모두 {rms_range} A — 정격의 {pct_range} %, 위험 과전류. 세 줄이 같이 붉다` / `… 위험 저전류. 세 줄이 같이 파랗다 (결상과 다름)` |
| 결상 | `{phase_label} {rms_A} A — 끊긴 상, 나머지 두 상({others})에 전류가 몰림 ({others_rms_A} A, {others_pct} %)` |
| I₂/I₁ 눈금 | `I₂/I₁ {prev} → {value} — {mark_label} 수준({level}) 도달, 정상의 {x_normal}배` |
| 균형만 무너짐 | `세 상 모두 정상 범위 — 그러나 I₂/I₁ {value}, 정상({normal_level})의 {x_normal}배. 색은 정상, 숫자는 이상` |
| 단락 루프 | `빨간 단락 루프 표시 — {phase_label} 코일 {turns}턴의 절연이 깨진 위치 (시각적 표시, 순환전류는 모델에 없음)` |
| 장면 전환 | `장면 {label} — 입자 흐름 {slowmo_x}배 느리게 (실제 60 Hz)` |

"균형만 무너짐" 사건의 기준(정상 목표값의 5배 초과, 세 상 모두 정상)은 export 상수 `BALANCE_ONLY_FACTOR` 다. 장면 5 는 9.9배라 걸리고 다른 장면은 걸리지 않는다.

## 인과 카드·판별 매트릭스 요약 문구

인과 카드의 조치("권선 절연 진단", "레이저 정렬" 등)와 매트릭스 아래 한 줄 규칙("세 줄 같이 빨강 = 과부하 …")은 PDF 3장 멘트와 4장의 요약이며
시뮬레이션 결과가 아니다. 질문이 오면 "일반 정비 지침·판별 규칙"이라고 답한다.

## 고치는 법

`content/electrical/*.yaml` 을 고치고 새로고침. 숫자·상 이름은 직접 쓰지 말고 변수(`{ph_a}` 등)를 쓴다. `pytest tests` 가 미정의 변수와 PDF 불일치를 잡는다.
