# dashboard/CLAUDE.md — 모터 결함 시각화 설명 대시보드

> 이 문서는 상위 `CLAUDE.md`(디지털 트윈 결함 시각화)의 **후속 작업 지침**이다.
> 상위 문서의 절대 규칙(config 단일 출처, 정직성 표기, Phase별 보고·승인)은 그대로 유지된다.
> 이 문서와 상위 문서가 충돌하면, 대시보드 관련 사항은 이 문서를 따른다.

---

## 0. 너의 역할과 목표

너는 **산업 데이터 시각화 프론트엔드 엔지니어이자 기술 커뮤니케이터**다.

Phase 0~5에서 만든 Isaac Sim 결함 애니메이션을 **한 화면의 설명형 대시보드**로 묶는다.
대시보드를 보는 사람은 소셜벤처 경진대회 심사위원이다. 모터를 모르는 사람도 아래 세 가지를 이해해야 한다.

1. **무엇이 보이는가** — 애니메이션에서 어느 부품이 왜 빨갛게/파랗게 변하는가
2. **기준이 무엇인가** — 몇 도에서 베어링이 붉어지는가, 몇 암페어부터 과전류/저전류인가
3. **그래서 무엇이 좋은가** — VIGENT가 고장 전에 어느 시점에 경보를 줄 수 있는가

발표 중 발표자(김선우)가 이 대시보드 하나로 설명을 진행할 수 있어야 한다.

---

## 1. 절대 규칙

1. **숫자는 절대 직접 쓰지 마라.** 모든 임계값·정격값·색상은 상위 프로젝트의 `config/*.yaml`에서, 모든 시계열은 `logs/*.csv`에서 가져온다. 이를 위해 **export 스크립트가 대시보드용 JSON을 생성**하고, 대시보드는 그 JSON만 읽는다. (애니메이션과 대시보드의 숫자가 다르면 심사 질의에서 치명적이다.)
2. **완전 오프라인 동작.** 발표장 인터넷을 믿지 마라. 모든 라이브러리·폰트·영상은 로컬에 번들한다. CDN 사용 금지.
3. **Isaac Sim 실시간 연동은 MVP 범위가 아니다.** 녹화된 mp4 + 로그 CSV를 동기 재생하는 방식으로 만든다. (실시간 연동은 선택 과제로 9장에 둔다.)
4. **정직성 표기 유지.** 화면에 항상 `시뮬레이션 기반 추정값` 및 `정격 기준: 2.2 kW 범용 전동기 대표값` 라벨을 표시한다.
5. **용어를 정확히 구분한다.** 애니메이션의 색은 **전류(과전류/저전류)** 기준이다. 전압(과전압/저전압)은 전류 이상을 일으키는 **원인**으로 설명한다. 두 개념을 섞어 쓰지 마라. (6.3절 참고)
6. 각 Phase 종료 시 멈추고 보고한다: ① 한 일 ② 변경 파일 ③ 실행 방법 ④ 확인 방법(스크린샷) ⑤ 한계·다음 제안.
7. 설명 문구는 **한국어**, 중학생도 이해할 수 있는 수준으로 쓰되 기술적으로 틀린 말은 쓰지 않는다. 전문 용어는 처음 등장할 때 괄호로 풀어 쓴다. 예: ITSC(권선 층간단락, 코일 선끼리 절연이 깨져 붙어버리는 고장)

## 2. 기술 스택

- **Vite + React + TypeScript**, 차트는 **Apache ECharts**(로컬 번들), 스타일은 CSS 변수 기반
- 빌드 결과(`dashboard/dist/`)는 `npx vite preview` 또는 동봉한 간단한 로컬 서버 스크립트(`run_dashboard.bat` / `.sh`)로 **더블클릭 실행**이 가능해야 한다.
- 데이터 준비는 Python 스크립트(`dashboard/tools/export_dashboard_data.py`)로 한다. 상위 프로젝트의 `engine/` 모듈(RMS, 대칭좌표 계산)을 재사용하고 계산 로직을 복제하지 마라.

```
dashboard/
├── CLAUDE.md
├── tools/export_dashboard_data.py   # config + logs → public/data/*.json
├── public/
│   ├── data/                        # thresholds.json, scenarios.json, timeseries_*.json, glossary.json
│   └── media/                       # 녹화 mp4 (모듈 A, B, 통합, 자동 재생 시나리오)
├── src/
│   ├── components/                  # VideoPanel, SyncedCharts, ExplainPanel, ThresholdTable, FaultCards, Legend, HUDBar
│   ├── content/                     # 설명 문구(마크다운/TS 상수) — 숫자는 JSON 참조로만
│   └── state/                       # 재생 시간 동기화 스토어
└── run_dashboard.(bat|sh)
```

## 3. Phase D0 — 탐색 (코드 작성 전)

1. 상위 프로젝트의 `config/`, `logs/`, 녹화 영상 위치를 확인하고 목록을 보고한다.
2. 아래 영상이 있는지 확인한다. 없으면 기존 녹화 절차(`docs/record_demo.md`)로 생성할 것을 제안하고 승인받는다.
   - 모듈 A 단독(베어링 결함 등), 모듈 B 단독(정상/4-turn/12-turn ITSC/과부하/결상), 통합 자동 재생 시나리오
3. **영상과 로그의 시간축이 맞는지** 확인한다. 녹화 시작 시각과 로그 t=0의 오프셋을 측정해 `scenarios.json`에 기록할 방법을 제안한다. 시간축이 안 맞으면 동기 재생 자체가 무의미하므로 여기서 반드시 해결한다.
4. `config/thermal.yaml`, `config/electrical.yaml`의 실제 임계값을 읽어 **현재 값 요약표**를 보고한다. (대시보드에 들어갈 숫자를 발표자가 미리 확인하기 위함)
5. **애니메이션 영상 바탕화면 저장**: 확인·생성된 모든 녹화 영상(mp4)을 바탕화면의 `모터결함_애니메이션` 폴더에도 복사한다.
   - 바탕화면 경로는 추측하지 말고 OS에서 조회한다. Windows는 OneDrive 바탕화면 리디렉션(`%USERPROFILE%\OneDrive\Desktop`, `바탕 화면` 한글 폴더명 등)이 있을 수 있으므로 PowerShell `[Environment]::GetFolderPath('Desktop')`로 실제 경로를 얻는다. Linux/macOS는 `xdg-user-dir DESKTOP` 또는 `~/Desktop`을 확인한다.
   - 파일명은 내용을 알 수 있게 정리한다: `01_기계_베어링결함.mp4`, `02_전기_정상.mp4`, `03_전기_ITSC_4turn.mp4`, `04_전기_ITSC_12turn.mp4`, `05_전기_과부하.mp4`, `06_전기_결상.mp4`, `07_통합_자동재생.mp4` 등
   - **복사**만 한다. 대시보드용 `public/media/`와 원본 녹화 위치의 파일은 그대로 유지한다.
   - 이후 영상을 다시 녹화하거나 수정하면 바탕화면 폴더도 함께 갱신하고, 보고 시 바탕화면 폴더의 최종 파일 목록을 보여준다.

## 4. 화면 구성 (1920×1080 발표 화면 기준, 16:9)

```
┌──────────────────────────────────────────────────────────────────────┐
│ HUDBar: 프로젝트명 · 모드 탭[기계 | 전기 | 통합] · 상태 등급 뱃지 · 라벨  │
├───────────────────────────────┬──────────────────────────────────────┤
│                               │  ExplainPanel                         │
│   VideoPanel                  │  - 지금 무슨 일이 일어나는가 (자동 갱신)│
│   (Isaac Sim 녹화 영상)         │  - 왜 이 색인가                        │
│   + 챕터 마커 타임라인           │  - 현장에서는 무엇을 해야 하나          │
│                               │                                       │
├───────────────────────────────┴──────────────────────────────────────┤
│ SyncedCharts: 온도 / 상별 전류 RMS / I₂·I₁ (임계 구간 배경색 + 재생 커서) │
├──────────────────────────────────────────────────────────────────────┤
│ 하단 탭: [색상 기준표] [결함 도감] [용어 풀이]                            │
└──────────────────────────────────────────────────────────────────────┘
```

- **발표 모드**(F 키): 전체화면, 글자 크기 확대, 하단 탭 숨김. **←/→ 키**로 시나리오 챕터 이동, **스페이스**로 재생/정지. 발표자가 마우스 없이 진행할 수 있어야 한다.
- 다크 테마 기본(빨강 발광·파랑이 잘 보이도록), 라이트 테마 토글 제공.
- 색은 상위 `config/colors.yaml`과 **완전히 동일**해야 한다. 영상 속 빨강과 대시보드 빨강이 달라 보이면 안 된다.
- 색각 이상 관람자를 고려해 상태는 색 + 아이콘/텍스트(예: ▲ 과전류, ▼ 저전류)로 함께 표시한다.

## 5. 동기화 동작 (핵심 기능)

- 영상의 `currentTime`이 **단일 시간 소스**다. 영상이 재생되면:
  - 차트의 세로 커서가 같은 시각으로 이동
  - HUDBar의 상태 뱃지(정상/주의/경고/위험)가 해당 시각 값으로 갱신
  - ExplainPanel 문구가 해당 챕터의 설명으로 교체 (부드러운 페이드)
- 차트를 클릭하면 영상이 그 시각으로 이동한다(양방향 동기화).
- 챕터 마커 예시(통합 시나리오, 실제 타임라인은 `config/scenario.yaml`에서 가져옴):
  1. 정상 운전 → 2. 베어링 열화 → 3. ITSC 초기(4-turn) → 4. ITSC 진행(12-turn) → 5. VIGENT 경보 시점
- 차트에는 **"VIGENT 조기 경보 가능 시점"** 을 세로 점선으로 표시하고, 실제 위험 도달 시점과의 **시간 차(리드 타임)** 를 라벨로 보여준다. 이것이 사업 가치를 보여주는 핵심 장면이다.

## 6. 설명 콘텐츠 (하단 탭 + ExplainPanel)

### 6.1 [색상 기준표] — 기계적 결함 (온도)
`thresholds.json`에서 생성한다. 부품별로 행을 만든다: DE 베어링, NDE 베어링, 고정자 권선, 로터, 커플링, 브레이크, 하우징.

| 열 | 내용 |
|---|---|
| 부품 | 이름 + 작은 모터 단면 아이콘에서 위치 하이라이트 |
| 정상 | 원래 재질 색 스와치 + 온도 범위 |
| 주의 | 주황 스와치 + 온도 범위 |
| 경고 | 빨강 스와치 + 온도 범위 |
| 위험 | 빨강 발광·맥동 스와치(애니메이션) + 온도 범위 |
| 이 부품이 뜨거워지는 이유 | 한 줄 설명 (예: 베어링 — 마모·윤활 부족으로 마찰이 커짐) |

- 문장 예시(숫자는 JSON 치환): `"구동측 베어링은 {warn}°C를 넘으면 붉게 변하고, {danger}°C 이상에서 깜빡이며 발광합니다."`
- 베어링·권선처럼 부품별 임계값이 다르면 반드시 부품별 값을 쓴다. 공통값으로 뭉뚱그리지 마라.

### 6.2 [색상 기준표] — 전기적 결함 (전류)
`electrical.yaml`의 비율 임계값과 `motor.yaml`의 정격값을 곱해 **실제 암페어로 환산해서** 보여준다. Δ결선이므로 **선전류(케이블)와 상전류(권선)를 두 열로 분리**한다.

| 상태 | 색 | 기준 (정격 대비) | 케이블 선전류 | 권선 상전류 |
|---|---|---|---|---|
| 위험 과전류 | 빨강(강) | r > 1.25 | 자동 계산 | 자동 계산 |
| 주의 과전류 | 빨강(약) | r > 1.10 | 〃 | 〃 |
| 정상 | 초록 | 0.85 ≤ r ≤ 1.10 | 〃 | 〃 |
| 주의 저전류 | 파랑(약) | r < 0.85 | 〃 | 〃 |
| 위험 저전류(결상 의심) | 파랑(강) | r < 0.5 | 〃 | 〃 |

- 현재 config 기준 참고값(검증용, 대시보드에는 반드시 계산값 사용): 선전류 4.7 A 기준 → 5.17 / 5.88 / 4.0 / 2.35 A, 상전류 2.7 A 기준 → 2.97 / 3.38 / 2.30 / 1.35 A. export 결과가 이와 다르면 config가 바뀐 것이므로 보고하라.
- **I₂/I₁(역상분 비율) 게이지**를 함께 둔다: 정상 ≈ 0.006, 4-turn ITSC ≈ 0.104, 12-turn ITSC ≈ 0.269 지점을 눈금으로 표시하고 한 줄 설명을 단다: "세 줄의 전류가 서로 얼마나 균형이 깨졌는지를 나타내는 숫자. 권선 단락은 전류 크기보다 이 숫자에서 먼저 드러납니다."

### 6.3 [용어 풀이] — 전압과 전류의 관계 (반드시 포함)
심사위원이 "과전압/저전압 아닌가요?"라고 물을 수 있으므로 명확히 설명한다.

- 애니메이션의 빨강/파랑은 **전류**의 많고 적음이다.
- **전압 이상은 전류 이상의 원인**이다. 특히 직관과 반대되는 점을 강조한다:
  - **저전압**: 부하가 걸린 유도전동기는 같은 힘을 내려고 전류를 더 끌어온다 → **과전류(빨강) + 권선 발열**
  - **과전압**: 무부하·경부하에서는 여자전류가 늘어 전류가 증가하고 철손이 늘어 발열한다
  - **전압 불평형**: 몇 %의 전압 불평형이 훨씬 큰 전류 불평형을 만든다 → 특정 상만 빨강/파랑
  - **결상**(한 상이 끊김): 끊긴 상은 파랑, 나머지 두 상은 빨강
- 위 설명은 **정성적 설명**으로 쓰고, 구체적인 배율 수치를 인용할 경우 출처(IEC/NEMA 규격 등)를 달 수 있을 때만 쓴다. 출처를 확신할 수 없으면 수치를 쓰지 마라.

### 6.4 [결함 도감] — 결함별 카드
시뮬레이션에 구현된 결함마다 카드 1장. 카드를 누르면 해당 결함 영상 구간으로 이동한다.

- 카드 구성: 결함 이름(쉬운 말 병기) / 원인 / **애니메이션에서 보이는 모습**(어느 부품, 무슨 색) / 판정 기준(JSON 수치) / 방치하면 생기는 일 / 현장 조치 / VIGENT가 감지하는 신호(온도·전류·I₂/I₁·진동 중 무엇)
- 대상: 베어링 결함, 축 오정렬, 냉각팬 고장, 브레이크 끌림, 과부하, 공급전압 불평형, 결상, ITSC(4-turn / 12-turn)

### 6.5 ExplainPanel 문구 원칙
- 챕터당 3문장 이내: **지금 무엇이 보이는가 → 왜 그런가 → 무엇을 해야 하는가**
- 문구는 `src/content/`에 모아 두어 발표자가 코드 수정 없이 고칠 수 있게 한다.

## 7. 작업 순서 (Phase별 승인 후 진행)

| Phase | 내용 | 완료 기준 |
|---|---|---|
| D0 | 탐색, 영상·로그 시간축 확인, 임계값 요약 보고 | 오프셋 측정 방법 확정 |
| D1 | export 스크립트 → JSON 생성 + 스키마 문서 | pytest: JSON 수치가 config·로그와 일치 |
| D2 | 레이아웃, 테마, 색 일치, 정적 기준표 | 1920×1080 스크린샷 |
| D3 | 영상 ↔ 차트 ↔ 설명 양방향 동기화, 리드 타임 표시 | 챕터 이동 시 모든 패널 동시 갱신 |
| D4 | 설명 콘텐츠(기준표, 결함 도감, 용어 풀이) 작성 | 발표자 검토용 문구 목록 제출 |
| D5 | 발표 모드, 키보드 조작, 오프라인 빌드, 실행 스크립트 | 인터넷 차단 상태에서 더블클릭 실행 성공 |

MVP 필수: D0~D3 + D4의 색상 기준표·용어 풀이. 결함 도감은 시간이 부족하면 핵심 3종(베어링, 과부하, ITSC)만 먼저 만든다.

## B. 시간축 동기화 — D0 완료 기준 달성

`영상시각 = t_real_s + 2.006`

두 겹으로 보장한다.

1. 데모(`--record`)가 ffmpeg 를 직접 띄워 녹화 시작 ↔ 시나리오 시작 시각 차를 자동 기록한다
   (`motor_dt_viz/logs/recording_<이름>.json` 의 `video_offset_s`)
2. HUD 타임코드를 영상에 구워 눈으로 검증한다 (`--no_timecode` 로 끌 수 있다)

실측 오차: 영상 22 s → +0.066 초 / 62 s → +0.026 초 / 152 s → +0.046 초.
요구 기준 0.2 초 이내이고 시간이 지나도 오차가 커지지 않는다(드리프트 없음).

이 과정에서 **`t_wall`(프레임 수 × 1/60)이 실제 시간이 아니라는 버그**를 찾아 고쳤다.
렌더가 약 70 fps 라 시뮬레이션 시각이 17 % 빨리 흘러, 165초 시나리오가 141초에 끝나고 있었다.
시나리오 진행과 열 적분을 벽시계 dt 기준으로 바꿨고, CSV 에 `t_real_s` 컬럼을 추가했다.

## E. 녹화 시 주의 (실측으로 확인)

- **ffmpeg 의 `gdigrab -i title=` 은 Isaac Sim 에 쓸 수 없다.** Vulkan 으로 직접 그려서 창 DC 가
  갱신되지 않아, 녹화 내내 기동 직후 화면만 반복해서 찍힌다(62초 지점에도 시나리오 미시작 화면).
  `-i desktop` 에 `-offset_x/-offset_y/-video_size` 를 줘서 창 영역만 잘라낸다.
- 경로에 공백과 한글이 있어 `.bat` 에 절대 경로를 넘기면 인자가 깨진다. **상대 경로**를 쓴다.
- ffmpeg 종료는 stdin 에 `q` 를 보낸다. kill 하면 moov atom 이 없어 파일이 깨진다.
