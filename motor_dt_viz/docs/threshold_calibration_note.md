# 임계값 보정 가능성 메모 (샘플 L3 기준, config 변경 없음)

**결론: 지금 샘플로는 진동·베어링 임계값을 바꾸지 않는다.** 근거는 아래. 별도 지시가 있어도 이 메모의 한계를 전제로 한다.

## 1. 지금 임계값 (config/thresholds.yaml + config/motors/M1.yaml)

- M1 진동: ISO 10816-1 Class I (15 kW 미만, 소형기) — 경고 1.8 / 위험 4.5 mm/s
- 베어링 지표: 경고 2.0배 / 위험 5.0배 (포락선 BPFO 피크 / 정상)

## 2. 샘플(2.2 kW = M1, 진동 1축, g 추정)에서 본 분포

| 라벨 | n | 중앙값 | 95 % | 99 % | 최대 |
|---|---|---|---|---|---|
| 정상 (4대) | 680 | 0.161 | 0.278 | 0.288 | 0.298 |
| 베어링불량 (L-SF-04) | 240 | 0.212 | 0.223 | 0.230 | 0.237 |
| 축정렬불량 (L-DSF-01) | 207 | 0.105 | 0.117 | 0.125 | 0.133 |

같은 모터(L-SF-04) 정상 vs 베어링불량: 속도 RMS 0.198 → 0.212 mm/s (×1.07), 고주파 대역 RMS ×0.95, kurtosis 2.93 → 2.86, crest 3.8 → 3.7.

## 3. 왜 지금 바꾸지 않나

- 정상의 99 % 값(0.29 mm/s)이 현재 경고 하한(1.8)의 16 % 다. 경고선을 데이터 쪽으로 내리면(0.58 mm/s 같은 값) 베어링불량(중앙값 0.21)도 못 잡는다 — 이 샘플의 베어링불량은 속도 RMS 로 구분되지 않는다.
- 베어링 지표(포락선 BPFO 배율)는 베어링 번호가 없어 계산 자체가 안 됐다. 보정할 수치가 없다.
- 진동 단위가 설명서로 확정되지 않았다 (g 가정). m/s² 라면 값이 1/9.8 이 되어 결론이 바뀐다.
- 표본이 M1 한 용량·4대·하루치뿐이고, 결함 라벨은 모터당 한 종류라 '정상 vs 결함' 이 '모터 A vs 모터 B' 와 섞인다. 축정렬불량(L-DSF-01)은 오히려 그 모터의 정상보다 낮다.
- 측정 조건(팬 모터, 정속 연속, 1축)이 크레인 권상 모터(간헐·가변 부하)와 다르다.

## 4. 바꿀 수 있게 되는 조건

- 설명서로 진동 단위·센서 방향·베어링 모델이 확정되고, 같은 모터의 정상→결함 시계열(진행 과정)이 있으면: 정상 99 % 와 결함 1 % 사이에 경고선을 두는 방식으로 `config/thresholds.yaml`·`config/motors/*.yaml` 의 진동 경계를 모터 용량별로 제안할 수 있다.
- 그 전까지 상태 보드 라벨은 '시뮬레이션 기반 추정값' 을 유지하고 '공공 실측 데이터로 보정한 추정값' 으로 바꾸지 않는다.
